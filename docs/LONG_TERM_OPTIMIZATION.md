# 🔧 长期运行优化建议

本文档列出系统长期运行（数周/数月）时可能需要优化的环节。

---

## ✅ 已实现的优化

### 1. 内存管理
- ✅ **自动垃圾回收**：每个 trading cycle 结束后执行 `gc.collect()`
- ✅ **对话历史限制**：限制对话历史长度（最多20条）
- ✅ **文件读取优化**：API 只读取最后 80KB，避免加载整个文件

### 2. 磁盘空间管理
- ✅ **自动清理脚本**：清理旧备份和日志文件
- ✅ **备份文件管理**：自动清理超过7天的备份文件
- ✅ **日志轮转**：建议每周清理一次日志文件

### 3. 性能优化
- ✅ **工具调用缓存**：ToolCoordinator 缓存工具结果，减少重复调用
- ✅ **预算分配优化**：BudgetAllocator 根据市场条件分配工具预算
- ✅ **并行执行框架**：已实现并行执行结构（当前为优化顺序执行）

---

## ⚠️ 潜在优化点

### 1. JSONL 文件大小

**当前状态**：
- `discussion_actions.jsonl`：每次 trading cycle 追加记录
- `equity_history.jsonl`：每小时追加记录
- `filled_orders.jsonl`：每次交易追加记录

**潜在问题**：
- 长时间运行后，JSONL 文件可能变得很大（>100MB）
- 读取整个文件可能变慢

**当前优化**：
- API 只读取最后 80KB（约最后 100-200 条记录）
- 使用 `reversed()` 从新到旧读取

**建议**：
- ✅ **已足够**：当前优化已能处理大文件
- 如果文件 >500MB，可以考虑归档旧数据

### 2. 内存文件累积

**当前状态**：
- `memory/daily/`：每天创建一个 JSON 文件
- `memory/weekly/`：每周创建一个 JSON 文件
- `memory/monthly/`：每月创建一个 JSON 文件

**潜在问题**：
- 长时间运行后，daily 文件可能很多（>100个）

**当前优化**：
- ✅ **清理脚本**：`cleanup_old_memory.py` 清理今天之前的文件
- ✅ **自动维护**：每周维护任务自动清理

**建议**：
- ✅ **已足够**：清理脚本已实现
- 建议保留最近 30 天的 daily 文件

### 3. 日志文件大小

**当前状态**：
- `logs/api_task.log`：API 服务器日志
- 可能持续增长

**潜在问题**：
- 长时间运行后，日志文件可能很大（>100MB）

**建议**：
- ✅ **日志轮转**：每周清理一次旧日志
- ✅ **自动维护**：每周维护任务自动清理

### 4. 数据库查询性能

**当前状态**：
- 使用 JSONL 文件存储数据
- 每次查询读取整个文件（但只处理最后 N 条）

**潜在问题**：
- 文件很大时，读取可能变慢

**当前优化**：
- ✅ **文件读取优化**：只读取最后 80KB
- ✅ **限制返回数量**：API 默认只返回 100 条记录

**建议**：
- ✅ **已足够**：当前优化已能处理大文件
- 如果文件 >1GB，可以考虑使用数据库

## 🎯 推荐配置（数周运行）

### 最小配置（推荐）

1. ✅ **使用 Task Scheduler**（最简单）
2. ✅ **启用自动启动**（系统重启后自动运行）
3. ✅ **启用崩溃恢复**（进程崩溃后自动重启）
4. ✅ **设置每周维护**（自动清理旧文件）
5. ✅ **设置每日上传**（每天一次，节省预算）

### 监控指标

| 指标 | 正常范围 | 警告阈值 | 检查频率 |
|------|---------|---------|---------|
| API 响应时间 | <1s | 1-3s | 每周 |
| 内存使用 | <2GB | 2-4GB | 每周 |
| CPU 使用率 | <50% | 50-80% | 每周 |
| 数据目录大小 | <5GB | 5-10GB | 每周 |
| JSONL 文件大小 | <100MB | 100-500MB | 每月 |

---

## 📝 维护计划

### 每周（自动）

- ✅ **自动清理**：每周日 2 AM 自动运行维护脚本
- ✅ **清理内容**：
  - 旧备份文件（>7天）
  - 旧日志文件（>30天）
  - 旧内存文件（>30天）

### 每月（手动）

- ✅ **重启 API 服务器**：确保最佳性能
- ✅ **检查数据完整性**：验证 portfolio_state.json 和交易记录
- ✅ **归档旧数据**：如果数据目录 >5GB，考虑归档
