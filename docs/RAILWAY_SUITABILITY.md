---

### 2. **Ollama 配置**

**问题**：Railway 上无法运行本地 Ollama

**解决方案**：

#### 选项 A：使用云 LLM API（推荐）

修改代码使用云 LLM 服务：
- OpenAI API
- Anthropic API
- 或其他云 LLM 服务

**优点**：
- ✅ 不需要本地 Ollama
- ✅ 更稳定
- ✅ 更快速

**缺点**：
- ⚠️ 需要 API 密钥
- ⚠️ 可能有费用

#### 选项 B：使用 Railway 的 Ollama 服务

在 Railway 上部署 Ollama：
- 需要自定义 Dockerfile
- 需要更多资源

**优点**：
- ✅ 可以使用本地模型

**缺点**：
- ⚠️ 配置复杂
- ⚠️ 资源消耗大

#### 选项 C：混合部署（推荐）

- **后端 API**：部署到 Railway（处理交易逻辑）
- **LLM 服务**：使用云 API 或本地 Ollama（通过环境变量配置）

---

### 3. **环境变量配置**

**需要在 Railway 设置**：
```
FRED_API_KEY=your_key_here
OLLAMA_HOST=https://your-ollama-service.com  # 如果使用云 Ollama
OPENAI_API_KEY=your_key_here  # 如果使用 OpenAI
```

**设置方法**：
1. Railway 项目 → Variables
2. 添加环境变量
3. 重新部署

---

### 4. **数据持久化**

**Railway 特点**：
- ⚠️ 文件系统是临时的（重启会丢失）
- ✅ 但你的系统使用 JSON 文件存储数据

**解决方案**：
- ✅ 使用 Railway 的 Volume（持久化存储）
- ✅ 或使用外部数据库（PostgreSQL、MongoDB）
- ✅ 或使用 Railway 的 PostgreSQL 插件（免费层）

**当前系统**：
- 使用 JSON 文件存储（`data/logs/`）
- 需要配置 Volume 来持久化
