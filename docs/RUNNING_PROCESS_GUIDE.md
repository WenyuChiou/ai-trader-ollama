# 系统运行流程指南

**更新时间**: 2025-11-14  
**目标**: 详细说明系统从启动到日常运行的完整流程和注意事项

---

## 🚀 系统启动流程

### 第一步：环境准备

**1. 检查Python环境**
```powershell
python --version  # 需要 Python 3.10+
```

**2. 启动Ollama服务**（必须）
```powershell
# 在单独的终端窗口运行（保持运行）
ollama serve

# 验证Ollama是否运行
curl http://localhost:11434/api/version
```

**3. 检查模型是否已下载**
```powershell
ollama list  # 确认 deepseek-r1 在列表中

# 如果没有，下载模型
ollama pull deepseek-r1
```

**4. 设置API密钥（可选但推荐）**
```powershell
# FRED API密钥（用于经济数据）
$env:FRED_API_KEY="your_api_key_here"
```

---

### 第二步：初始化数据

**首次运行前必须初始化**
```powershell
# 从项目根目录运行
python scripts/init_data.py
```

**这会创建**:
- `data/logs/portfolio_state.json` - 初始投资组合（$10,000现金）
- `data/logs/` 目录结构
- 所有必要的日志文件

---

### 第三步：启动API服务

**选择运行方式**:

#### 方式1：后台服务（推荐 - 关闭CMD也能运行）

**A. Windows Service（需要NSSM）**
```powershell
# 右键点击，选择"以管理员身份运行"
scripts\start_api_service_admin.bat
```

**B. 任务计划程序（无需额外软件）⭐ 最简单**
```powershell
# 右键点击，选择"以管理员身份运行"
scripts\start_api_task_admin.bat
```

#### 方式2：窗口模式（开发/测试）

**稳定版本（自动重启）**
```powershell
.\scripts\start_api_stable_bypass.ps1
```

**快速重启（日常使用）**
```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\restart_api_fast.ps1
```

**验证API是否运行**:
```powershell
# 检查端口8000是否被占用
Get-NetTCPConnection -LocalPort 8000

# 或访问
curl http://localhost:8000/api/market/status
```

---

### 第四步：启动前端

**启动前端服务器**
```powershell
cd frontend
python -m http.server 8080
```

**访问仪表板**
```
http://localhost:8080/monitor.html
```

## 📊 日常运行流程

### 市场开放时段（9:30 AM - 4:00 PM EST）

**自动流程**:
1. **每30分钟自动执行一次交易循环**
   - 9:30 AM - 第一次执行
   - 10:00 AM - 第二次执行
   - 10:30 AM - 第三次执行
   - ... 依此类推
   - 3:30 PM - 最后一次执行

2. **每次交易循环包含**:
   ```
   ┌─────────────────────────────────────┐
   │ 1. 数据收集 (5-10秒)                │
   │    - 获取118+股票的市场数据          │
   │    - 计算技术指标                    │
   │    - 获取经济指标和市场情绪          │
   └─────────────────────────────────────┘
            ↓
   ┌─────────────────────────────────────┐
   │ 2. 多Agent分析 (30-60秒)            │
   │    - Market Analyst: 宏观趋势        │
   │    - Technical Analyst: 价格模式     │
   │    - Fundamental Analyst: 估值       │
   │    - Sentiment Analyst: 市场心理     │
   │    - Risk Analyst: 风险评估          │
   └─────────────────────────────────────┘
            ↓
   ┌─────────────────────────────────────┐
   │ 3. 风险评估 (10-20秒)               │
   │    - 持仓集中度分析                  │
   │    - 市场风险评估                    │
   │    - 仓位大小建议                    │
   └─────────────────────────────────────┘
            ↓
   ┌─────────────────────────────────────┐
   │ 4. 交易决策 (5-10秒)                │
   │    - 生成买卖订单                    │
   │    - 应用仓位限制（单股最多15%）     │
   │    - 使用当前市价立即执行            │
   └─────────────────────────────────────┘
            ↓
   ┌─────────────────────────────────────┐
   │ 5. 订单执行                         │
   │    - 市价单：立即以当前价格成交      │
   │    - 更新投资组合                    │
   │    - 记录已实现损益（SELL订单）      │
   └─────────────────────────────────────┘
            ↓
   ┌─────────────────────────────────────┐
   │ 6. 投资组合更新                     │
   │    - 更新portfolio_state.json       │
   │    - 记录净值历史（每30分钟）        │
   │    - 保存记忆快照                    │
   └─────────────────────────────────────┘
   ```

3. **净值记录**:
   - 每30分钟自动记录一次净值到 `equity_history.jsonl`
   - 包含：现金、持仓价值、总价值、P&L

---

### 市场关闭时段（4:00 PM - 9:30 AM next day）

**自动流程**:
1. **自动交易停止**
   - 系统检测到市场关闭
   - 自动停止30分钟定时器
   - 显示 "Market Closed - Manual Only"

2. **可以手动运行分析**
   - 点击 "Run Analysis" 按钮
   - 系统会运行Agent分析和讨论
   - **但不会创建任何订单**

3. **自动清理pending订单**
   - 如果市场关闭时还有pending订单，系统会自动清理
   - 因为市价单不应该有pending状态

---

## 🔄 完整交易循环详解

### 阶段1：数据收集

**执行内容**:
- 获取NASDAQ-100股票列表（118+股票）
- 获取实时价格数据
- 计算技术指标（RSI, MACD, BB等）
- 获取市场指数（S&P 500, Dow, NASDAQ）
- 获取经济指标（VIX, Fear & Greed Index）
- 获取新闻数据（通过news_scan工具）

**耗时**: 5-10秒

---

### 阶段2：多Agent分析

**Agent执行顺序**:

1. **Market Analyst** 🌐
   - 分析宏观趋势
   - 使用工具：`get_market_indices`, `get_sector_rotation`, `get_market_breadth`
   - 输出：市场整体观点

2. **Technical Analyst** 📈
   - 分析价格模式和技术指标
   - 使用工具：`get_advanced_indicators`, `get_support_resistance`
   - 输出：技术分析观点

3. **Fundamental Analyst** 💼
   - 分析财务数据和估值
   - 使用工具：`get_company_fundamentals`, `get_earnings_history`
   - 输出：基本面分析观点

4. **Sentiment Analyst** 😊
   - 分析市场情绪和新闻
   - **强制使用工具**：`news_scan`（自动添加）
   - 使用工具：`fear_greed`, `vix_term`, `news_scan`
   - 输出：情绪分析观点

5. **Risk Analyst** 🛡️
   - 分析风险（基于所有Agent的观点 + 当前持仓）
   - 输入：当前持仓（包括P&L和仓位%）、投资组合价值、讨论风险信号
   - 输出：风险评估报告

6. **Discussion Coordinator** 💬
   - 协调所有Agent的讨论
   - 生成综合摘要
   - 输出：最终市场观点和交易建议

**耗时**: 30-60秒

---

### 阶段3：风险评估

**执行内容**:
- 分析当前持仓集中度
- 检查单股仓位是否超过15%
- 检查总仓位是否超过85%
- 评估市场风险（VIX, Fear & Greed）
- 生成仓位大小建议

**耗时**: 10-20秒

---

### 阶段4：交易决策

**执行内容**:
- Trader Agent根据所有分析生成交易决策
- 应用仓位限制（单股最多15%）
- 生成BUY/SELL订单列表
- 计算订单数量（基于可用资金和仓位限制）

**耗时**: 5-10秒

---

### 阶段5：订单执行

**BUY订单执行**:
```
1. 获取当前市价
2. 检查可用资金
3. 创建订单（limit_price = current_price）
4. 立即标记为FILLED
5. 更新投资组合（portfolio.buy()）
6. 记录到filled_orders.jsonl
```

**SELL订单执行**:
```
1. 获取当前市价
2. 检查持仓数量
3. 创建订单（limit_price = current_price）
4. 执行卖出（portfolio.sell()）- 计算realized_pnl
5. 立即标记为FILLED（传递realized_pnl）
6. 记录到filled_orders.jsonl（包含realized_pnl）
```

**关键点**:
- ✅ 所有订单都是**市价单**（立即成交）
- ✅ 订单状态应该是**FILLED**（不是PENDING）
- ✅ SELL订单会记录**realized_pnl**（已实现损益）

**耗时**: 1-2秒

---

### 阶段6：投资组合更新

**执行内容**:
- 更新 `portfolio_state.json`（现金、持仓）
- 记录净值到 `equity_history.jsonl`（每30分钟）
- 保存记忆快照到 `memory/daily/YYYY-MM-DD.json`
- 记录对话到 `discussion_actions.jsonl`

**耗时**: 1-2秒

## ⚠️ 关键注意事项

### 1. 系统启动注意事项

**必须检查**:
- ✅ Ollama服务正在运行（`ollama serve`）
- ✅ 模型已下载（`ollama list` 显示 deepseek-r1）
- ✅ Python环境正确（3.10+）
- ✅ 数据已初始化（`portfolio_state.json` 存在）
- ✅ API服务正常运行（端口8000可访问）

**常见问题**:
- ❌ Ollama未运行 → API无法调用LLM → 交易循环失败
- ❌ 模型未下载 → API无法调用LLM → 交易循环失败
- ❌ 数据未初始化 → 找不到portfolio_state.json → 交易循环失败

---

### 2. 市场时间注意事项

**市场开放时间**:
- **EST**: 9:30 AM - 4:00 PM
- **EDT**: 9:30 AM - 4:00 PM（夏令时）
- **自动交易**: 每30分钟执行一次

**市场关闭时间**:
- **EST**: 4:00 PM - 9:30 AM next day
- **自动交易**: 自动停止
- **手动分析**: 可以运行，但不创建订单

**时区设置**:
- ⚠️ **重要**: 确保服务器时区设置为EST/EDT
- ⚠️ 时区错误会导致市场时间判断错误

**节假日处理**:
- ✅ 系统自动跳过美国股市节假日
- ✅ 使用 `trading_days.py` 检查交易日

---

### 3. 订单执行注意事项

**订单类型**:
- ✅ 所有订单都是**市价单**（不是限价单）
- ✅ 市价单保证立即成交（使用当前价格）

**订单状态**:
- ✅ 正常状态：**FILLED**（已成交）
- ❌ 异常状态：**PENDING**（不应该出现，除非市场关闭时创建）

**订单日期**:
- ✅ 使用 `placed_at` 字段（包含完整时间戳）
- ❌ 不再使用 `order_date` 字段（已移除）

**SELL订单P&L**:
- ✅ SELL订单会记录 `realized_pnl`（已实现损益）
- ✅ 包含：`realized_pnl`, `realized_pnl_pct`, `cost_basis`, `proceeds`

---

### 4. 数据记录注意事项

**净值记录**:
- ✅ 每30分钟自动记录一次
- ✅ 记录到 `equity_history.jsonl`
- ✅ 包含：现金、持仓价值、总价值、P&L

**订单记录**:
- ✅ FILLED订单记录到 `filled_orders.jsonl`
- ✅ PENDING订单记录到 `pending_orders.jsonl`（应该很少或为空）

**对话记录**:
- ✅ 所有Agent对话记录到 `discussion_actions.jsonl`
- ✅ 包含：分析内容、工具调用、讨论摘要

**记忆记录**:
- ✅ 每日记忆快照保存到 `memory/daily/YYYY-MM-DD.json`
- ✅ 包含：市场观点、讨论、风险报告、交易决策

---

### 5. 工具调用注意事项

**新闻工具强制使用**:
- ✅ Sentiment Analyst **必须**使用 `news_scan` 工具
- ✅ 即使Agent没有请求，系统也会自动添加
- ✅ 确保新闻分析被包含在情绪分析中

**工具调用限制**:
- ✅ 每个Agent最多调用 `discussion_tool_budget` 个工具（默认15）
- ✅ 工具调用结果会传递给Agent进行分析

---

### 6. 自动交易注意事项

**市场开放时**:
- ✅ 自动启动30分钟定时器
- ✅ 每30分钟自动执行一次交易循环
- ✅ 也可以手动触发（点击 "Start Trading"）

**市场关闭时**:
- ✅ 自动停止30分钟定时器
- ✅ 显示 "Market Closed - Manual Only"
- ✅ 只能手动运行分析（不创建订单）

**状态监控**:
- ✅ 系统每60秒检查一次市场状态
- ✅ 市场状态变化时自动切换（开放→关闭，关闭→开放）

---

### 7. 错误处理注意事项

**API崩溃**:
- ✅ 如果使用Windows Service或任务计划程序，会自动重启
- ✅ 如果使用窗口模式，需要手动重启

**Ollama连接失败**:
- ❌ 如果Ollama服务停止，API无法调用LLM
- ✅ 检查Ollama是否运行：`curl http://localhost:11434/api/version`

**数据文件损坏**:
- ⚠️ 如果数据文件损坏，可能需要重新初始化
- ✅ 定期备份 `data/logs/` 目录

**网络问题**:
- ⚠️ 如果网络中断，无法获取市场数据
- ✅ 检查网络连接和API密钥

## 🔍 故障排查

### 问题1：订单状态为PENDING

**可能原因**:
- 市场关闭时创建了订单（不应该发生）
- SELL订单执行顺序错误（已修复）

**解决方法**:
- 检查市场状态检测逻辑
- 检查订单执行代码
- 手动清理pending订单

---

### 问题2：对话被截断

**可能原因**:
- 后端长度限制（已移除）
- 前端显示高度不足（已增加）

**解决方法**:
- 检查后端代码（应该没有长度限制）
- 检查前端CSS（高度应该为800px）

---

### 问题3：新闻工具未使用

**可能原因**:
- Sentiment Analyst没有请求工具
- 强制添加逻辑未生效

**解决方法**:
- 检查后端日志（应该有 "Adding news_scan" 消息）
- 重启API服务

---

### 问题4：自动交易未启动

**可能原因**:
- 市场状态检测错误
- 前端JavaScript错误

**解决方法**:
- 检查市场状态API响应
- 检查浏览器控制台错误
- 手动点击 "Start Trading"
