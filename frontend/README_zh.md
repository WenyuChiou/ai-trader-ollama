## 🚀 快速开始

### 先决条件

- **不需要 Node.js！** 前端是纯 HTML 文件
- 只需要 Python 的 HTTP 服务器（Python 3.6+）

### 启动前端服务器

#### 方法 1：Python HTTP 服务器（推荐）

```bash
cd frontend
python -m http.server 8080
```

**然后在浏览器中打开：** `http://127.0.0.1:8080/monitor.html`

#### 方法 2：PowerShell 脚本（Windows）

```powershell
cd frontend
.\start_frontend_server.ps1
```

### 验证连接

- ✅ **绿点** + "已连接"：API 正在运行
- ❌ **红点** + "已断开"：API 未运行或连接错误

## ✨ 功能

### 实时监控

- 📊 **投资组合概览**：总资产、现金、权益价值、总盈亏
- 📈 **权益历史图表**：显示资产价值随时间的变化
- 💼 **持仓详情**：显示所有持仓详情（数量、成本、市场价值、未实现盈亏）
- 📋 **执行详情**：显示所有交易记录（买入/卖出、价格、数量、状态）
- 💬 **代理对话**：实时显示代理分析和讨论内容

### 控制功能

- ▶️ **开始交易**：手动触发交易周期
- 🔄 **自动交易**：系统根据市场状态自动管理
  - **交易时间**：每 5 分钟自动运行
  - **非交易时间**：检查明天是否已计划，如果需要则执行计划
  - **状态显示**：实时状态指示器（🟢 运行中 / ⚪ 等待中 / 🔴 错误）
- 🔄 **刷新**：手动刷新数据

### 数据更新

- **自动刷新**：每 60 秒自动刷新数据
- **快速轮询**：手动触发后，10 秒内快速轮询（每秒一次）
- **去重**：自动删除重复的交易记录

### 交易时间支持

- **交易时间**：显示实时数据、投资组合、图表和订单
- **非交易时间**：显示历史数据、对话历史和明天的待处理订单
- **权益图表**：始终显示历史权益趋势（如果可用，包括今天的数据）

## 🔌 API 集成

前端通过以下 API 端点与后端通信：

| 功能 | API 端点 | 描述 |
|----------|--------------|-------------|
| 投资组合数据 | `GET /api/portfolio/real-time` | 获取实时投资组合状态 |
| 权益历史 | `GET /api/portfolio/equity-history` | 获取权益历史记录 |
| 交易记录 | `GET /api/trades/recent` | 获取最近的交易记录 |
| 代理对话 | `GET /api/agents/conversations` | 获取代理对话记录 |
| 执行交易 | `POST /api/trading/execute-trade` | 执行交易周期 |
| 市场状态 | `GET /api/market/is-open` | 检查市场是否开放 |

**API 地址配置**：默认 `http://127.0.0.1:8000`，可以通过修改 `monitor.html` 中的 `API_BASE` 变量来修改。

## ⚙️ 配置

### API 地址配置

修改 `monitor.html` 中的 `API_BASE` 变量：

```javascript
const API_BASE = 'http://127.0.0.1:8000';
```


```javascript
const CONVERSATIONS_LIMIT = 30;  // 最多显示 30 条对话

```

## 📖 使用指南

### 1. 查看投资组合

**概览卡片**显示：
- 总资产：总资产价值
- 总盈亏：总利润/亏损（金额和百分比）
- 现金：现金余额
- 权益价值：持仓市场价值

**持仓表**显示：
- 代码：股票代码
- 数量：持仓数量
- 平均成本：平均成本
- 当前价格：当前价格
- 市场价值：市场价值
- 未实现盈亏：未实现利润/亏损（金额和百分比）
- 权重：持仓权重

### 2. 查看交易记录

**执行详情**表显示：
- 时间：交易时间
- 订单日期：订单日期（明天的订单带有 "TOMORROW" 徽章）
- 代码：股票代码
- 方向：买入/卖出方向（BUY/SELL）
- 数量：交易数量
- 价格：交易价格
- 状态：订单状态（FILLED/PENDING）

**状态描述**：
- 🟢 **FILLED**：订单已成交（绿色）
- 🟡 **PENDING**：订单待处理（黄色）
- 🟠 **TOMORROW**：明天的待处理订单（橙色背景）

### 3. 查看代理对话

**概览页面**显示：
- 代理图标：每个代理都有专用图标
- 对话内容：完整的分析和讨论内容
- 工具使用：显示使用的工具和指标
- 时间戳：对话发生的时间

### 4. 执行交易

1. 点击 **"▶️ 开始交易"** 按钮
2. 等待代理分析完成（大约 30-60 秒）
3. 检查对话和交易记录是否已更新
4. 检查投资组合是否已更新

### 5. 自动交易（自动管理）

**系统自动管理自动交易 - 无需手动复选框：**

- **交易时间**：自动交易自动启动，每 5 分钟运行一次
- **非交易时间**：系统检查明天是否已计划
  - 如果未计划：执行一个计划周期，然后停止
  - 如果已计划：显示 "明天已计划，等待中" 状态
- **状态指示器**：实时状态显示，显示当前自动交易状态
  - 🟢 绿色：运行中 / 已完成
  - ⚪ 灰色：等待中 / 已计划
  - 🔴 红色：错误 / 失败
  - 🟡 黄色：检测中 / 检查中

**无需手动干预** - 系统根据市场状态智能管理自身！

### 6. 交易时间与非交易时间

**交易时间（9:30 AM - 4:00 PM）**：
- 实时投资组合数据更新
- 实时权益图表更新
- 实时订单状态更新
- 代理实时讨论

**非交易时间（其他时间）**：
- 显示最后投资组合快照
- 显示历史权益图表（如果可用，包括今天的数据）
- 显示对话历史
- 显示明天的待处理订单（带有 "TOMORROW" 徽章）
- 市场状态指示器："市场已关闭"

## 🔧 故障排除

### 连接错误

**症状**：显示 "连接错误" 或红点

**解决方案**：
1. 检查后端 API 是否正在运行：`curl http://localhost:8000/`
2. 检查浏览器控制台（F12）是否有错误
3. 确保 API 地址正确（默认：`http://127.0.0.1:8000`）

### 数据未更新

**症状**：数据未刷新或显示旧数据

**解决方案**：
1. 检查是否启用了自动刷新
2. 手动点击 **刷新** 按钮
3. 检查浏览器控制台是否有错误
4. 检查网络请求是否成功（F12 → 网络）

### 未实现盈亏显示错误

**症状**：未实现盈亏显示为市场价值而不是盈亏

**解决方案**：
- 前端已实现自动计算回退，如果后端未返回 `positions_pnl`，将从前端计算
- 如果仍然显示错误，检查后端 API 是否正确返回 `positions_pnl` 和 `total_cost` 字段
- 刷新页面后应正确显示

### 交易记录重复

**症状**：同一交易记录显示多次

**解决方案**：
- 前端已实现去重逻辑，如果仍然重复，检查后端 API 返回的数据
- 刷新页面后应正确去重

### 权益图表未显示

**症状**：非交易时间权益图表未显示

**解决方案**：
- 此问题已修复 - 非交易时间现在也显示历史权益图表
- 如果仍然未显示，检查是否调用了 `fetchEquityHistory()`
- 检查浏览器控制台是否有错误

### 测试问题排查

如果测试时遇到 "No trading decisions generated" 警告：

1. **检查 signal_score**：
   - 查看后端日志中的 `Debug: Top 10 stocks by signal_score`
   - 如果所有股票的 signal_score 都很低（< 0.5），这是正常的
   - 系统会自动使用 top 10 股票（即使 signal_score 很低）

2. **检查推荐股票**：
   - 查看 `Debug: enriched_market has X recommended_stocks`
   - 如果为 0，系统会使用 fallback 逻辑选择股票

3. **检查仓位限制**：
   - 如果已达到 `max_positions` 限制，可能不会生成新的买入订单
   - 检查 `[OPTIMIZATION] Position limits` 日志

4. **检查市场状态**：
   - 如果市场收盘且没有持仓，可能不会生成订单（这是正常的）
   - 查看 `[TRADING CYCLE]` 日志了解详细原因
