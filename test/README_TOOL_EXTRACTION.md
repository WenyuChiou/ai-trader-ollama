# 工具信息提取测试说明

## 概述

`test_tool_extraction.py` 是一个测试脚本，用于验证工具信息提取逻辑是否正确。它模拟前端的 `parseToolInfo` 函数和工具结果匹配逻辑。

## 功能

1. **解析工具信息** - 测试从工具内容字符串中提取工具名称和结果
2. **匹配工具条目** - 测试工具条目与讨论条目的匹配逻辑
3. **嵌套结构处理** - 检查双重嵌套 `ok/result` 结构的处理
4. **截断 JSON 处理** - 检查截断 JSON 的修复逻辑

## 使用方法

### 从项目根目录运行：
```bash
python test/test_tool_extraction.py
```

### 从 test 文件夹运行：
```bash
cd test
python test_tool_extraction.py
```

## 测试输出说明

### 1. 解析工具信息测试

测试每个工具条目的内容解析：
- ✅ **解析成功** - 成功提取工具名和结果
- ⚠️ **无结果数据** - 解析成功但没有结果数据
- ❌ **解析失败** - 无法解析工具内容

**结果类型：**
- `dict` - 对象（最佳情况）
- `list` - 数组
- `str` - 字符串（可能是截断的 JSON，需要进一步处理）

### 2. 匹配工具条目测试

测试讨论条目是否能正确匹配到对应的工具条目：
- ✅ **找到匹配** - 成功找到匹配的工具条目
- ❌ **未找到匹配** - 无法找到匹配的工具条目（可能是 agent 名称或日期不匹配）

### 3. 嵌套结构处理测试

检查是否还有未处理的嵌套 `ok/result` 结构：
- ✅ **所有嵌套结构都已正确处理** - 没有发现未处理的嵌套
- ⚠️ **发现未处理的嵌套结构** - 仍有嵌套结构未处理

### 4. 截断 JSON 处理测试

检查截断 JSON 的处理情况：
- ✅ **成功处理截断 JSON** - 成功修复并解析截断的 JSON
- ❌ **无法处理截断 JSON** - 无法修复截断的 JSON

## 常见问题

### Q: 为什么有些工具的结果类型是 `str` 而不是 `dict`？

A: 这通常表示 JSON 被截断了。测试脚本会尝试：
1. 检测 JSON 是否完整（`{` 和 `}` 数量是否匹配）
2. 如果完整，尝试解析为对象
3. 如果不完整，显示警告信息

### Q: 如何修复截断的 JSON？

A: 截断的 JSON 通常是因为后端在写入日志时限制了长度。可以：
1. 增加后端的截断限制（`backend/src/orchestrator/trading_cycle.py` 中的 `result_text` 长度限制）
2. 改进前端的 JSON 修复逻辑（`frontend/monitor.html` 中的 `parseToolInfo` 函数）

### Q: 为什么有些工具条目无法匹配到讨论条目？

A: 可能的原因：
1. **Agent 名称不匹配** - 讨论条目和工具条目的 agent 名称格式不一致（如 "Sentiment Analyst" vs "SentimentAnalyst"）
2. **日期不匹配** - 讨论条目和工具条目的日期不一致
3. **工具名称不匹配** - 工具名称不在讨论条目的 `tools_used` 列表中

## 改进建议

如果测试发现问题时，可以：

1. **检查后端日志格式** - 确保工具结果格式一致
2. **检查 agent 名称标准化** - 确保讨论和工具条目使用相同的 agent 名称格式
3. **增加截断限制** - 如果 JSON 经常被截断，考虑增加后端的长度限制
4. **改进 JSON 修复逻辑** - 如果截断 JSON 无法修复，改进前端的修复逻辑
